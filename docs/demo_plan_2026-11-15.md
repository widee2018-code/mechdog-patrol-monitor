# 중간 시연 계획서 (2026-11-15): MechDog 3마리 행렬 따라가기 + 포위

시연할 것은 두 가지입니다.

1. **행렬 따라가기:** A(정찰견)를 키보드로 몰면 B가 A를, C가 B를 마커로 따라간다.
2. **포위와 재정렬:** A는 멈춰 있고, B는 오른쪽, C는 왼쪽으로 포위한다. 사람이 확인하고 명령하면 B, C 순서로 줄 자리에 돌아와 카메라로 방향을 맞춘다.

**노트북 3대, 한 사람이 한 마리씩** 맡습니다. 두 시연은 자동으로 이어지지 않고, **따라가기 프로그램을 끄고 → 포위 프로그램을 켜는** 수동 전환입니다.

---

## 1. 역할과 노트북

| 노트북 | 맡는 로봇 | 실행하는 것 | 추가 역할 |
|---|---|---|---|
| **노트북 A (허브)** | A (정찰견) | **서버(허브)**, `teleop.py`로 A 조종 | 시연 진행, 구령 |
| **노트북 B** | B (확인견) | `marker_follow.py`, `contain_demo.py` (B) | |
| **노트북 C** | C (확인견, 맨 뒤) | `marker_follow.py`, `contain_demo.py` (C) | |

- 누가 어느 노트북을 맡을지는 시연 전에 정해서 아래 칸에 적기:
  노트북 A: ________ · 노트북 B: ________ · 노트북 C: ________
- **서버는 노트북 A에서만** 켭니다. 나머지 노트북은 서버에 붙어서 카메라 영상과 로봇 상태를 받습니다.
- 모든 노트북에서 대시보드 **http://<HUB_IP>:8000** 을 띄워 두면 같은 화면을 봅니다.
- 촬영과 넘어짐 대비는 손이 비는 사람이 맡습니다. 로봇이 이상하게 움직이면 **"정지"라고 외치고**, 그 로봇 담당은 자기 터미널에서 **Ctrl+C**.

## 3. 사전 준비 (시연 40분 전)

### 3-1. 코드 받기 (노트북 3대 모두)
```bash
cd "<저장소 폴더>/mechdog-patrol-monitor"
git checkout dev
git pull
pip install -r requirements.txt -r brain/requirements.txt
```
- 아래 명령은 모두 저장소 폴더에서 실행합니다.
- 명령은 **한 줄로** 적었습니다. macOS 터미널, Windows PowerShell 둘 다 그대로 붙여 넣으면 됩니다. 다른 점이 있으면 따로 적었습니다.

### 3-2. 허브 노트북 IP 확인 (노트북 A)
```bash
ipconfig getifaddr en0
```
Windows라면 `ipconfig` → Wi-Fi 어댑터의 IPv4 주소. 이 값이 `<HUB_IP>`이고 **모든 로봇의 `MONITOR`에 들어갑니다.**

### 3-3. IP 기록표 (공유: 단톡방 등에 올리기)

| 장치 | IP | 확인 방법 |
|---|---|---|
| 노트북 A (허브) | | 3-2 |
| 로봇견 A | | Thonny Shell `명령 대기: <IP> 9100` |
| 로봇견 B | | 〃 |
| 로봇견 C | | 〃 |
| 카메라 B | | 3-4 |
| 카메라 C | | 3-4 |

아래 명령의 `<HUB_IP>`, `<A_IP>`, `<B_IP>`, `<C_IP>`, `<CAM_B_IP>`, `<CAM_C_IP>`를 이 표의 값으로 바꿉니다.

### 3-4. 카메라 2대를 Wi-Fi에 붙이기 (노트북 B, C)
- 카메라 펌웨어(`firmware/mechdog_cam/`)는 `secrets.h`에 적힌 Wi-Fi로만 접속합니다. **시연 장소 Wi-Fi가 다르면** `secrets.h`를 고쳐 Arduino IDE로 다시 업로드합니다 (README "카메라 펌웨어 교체").
- **C 카메라에도 우리 펌웨어가 올라가 있는지 확인하세요.** 원래 Hiwonder 펌웨어면 자체 핫스팟으로만 동작합니다.
- IP는 업로드 후 Serial Monitor(115200)에 출력됩니다. 확인:
  ```bash
  curl http://<CAM_B_IP>/status
  ```
  `{"mode":"sta", ...}`면 정상. Windows PowerShell은 `curl.exe http://<CAM_B_IP>/status`.
- `mechdog-cam-a.local` 이름은 공유기에 따라 엉뚱한 주소로 가니 **IP를 직접 쓰세요**.
- **브라우저로 `:81/stream`을 직접 열지 마세요.** 카메라는 한 곳에만 영상을 보내서, 허브 서버가 못 받게 됩니다.

### 3-5. 각자 자기 로봇에 `secrets.py` 저장
각 노트북의 `firmware/secrets.py`(git에 없음, 없으면 `firmware/secrets.py.example`을 복사):
```python
WIFI_SSID = "YOUR_WIFI"          # 시연 장소 Wi-Fi 이름 (2.4 GHz)
WIFI_PASS = "YOUR_PASSWORD"      # 비밀번호
MONITOR = ("<HUB_IP>", 9000)     # ← 자기 노트북이 아니라 허브(노트북 A) IP
NAME = "B"                       # ← 자기 로봇 이름: A, B, C
```
1. 로봇견을 USB로 연결하고 Thonny에서 빨간 **Stop**.
2. 위처럼 채운 `firmware/secrets.py`를 열고 **파일 → 다른 이름으로 저장 → MicroPython 장치 → `secrets.py`** (덮어쓰기 예).
3. Shell에서 확인: `import secrets; print(secrets.NAME, secrets.MONITOR)`

> **`MONITOR`는 세 마리 모두 같은 값(허브 IP)**, **`NAME`은 각자 다른 값**입니다. 둘 중 하나라도 틀리면 대시보드에서 로봇이 안 보이거나 섞이고, 따라가기 준비 확인이 "dog not responding"으로 멈춥니다.

### 3-6. 각자 로봇에서 `dog_cmd.py` 실행
1. 배터리 스위치 **ON**, 로봇을 들거나 받침대에 올려 둠 (켜면 일어서려고 움직임).
2. Thonny에서 `firmware/dog_cmd.py`를 열고 **Run**.
3. Shell에 `명령 대기: <IP> 9100`이 나오면 IP를 기록표에 공유.
4. USB를 뽑아도 되는지 확인: 로봇이 계속 서 있고 `ping <IP>`가 응답하면 OK. 재부팅되면 USB를 꽂은 채로 진행.

> **LED 색:** 파랑 = 명령 대기, 초록 = 움직이는 중, 빨강 = 앞이 막힘(15 cm), 꺼짐 = 프로그램 멈춤

### 3-7. 허브 서버 켜기 (노트북 A, 시연 끝까지 켜 둠)
macOS:
```bash
CAMERAS="B=http://<CAM_B_IP>:81/stream,C=http://<CAM_C_IP>:81/stream" python -m uvicorn server.app:app --host 0.0.0.0 --port 8000 --timeout-graceful-shutdown 2
```
Windows PowerShell:
```powershell
$env:CAMERAS="B=http://<CAM_B_IP>:81/stream,C=http://<CAM_C_IP>:81/stream"; python -m uvicorn server.app:app --host 0.0.0.0 --port 8000 --timeout-graceful-shutdown 2
```
- **방화벽:** 다른 노트북과 로봇이 허브에 붙을 수 있게 허용해야 합니다. 처음 실행할 때 "들어오는 연결 허용?"이 뜨면 **허용**. (macOS: 시스템 설정 → 네트워크 → 방화벽, Windows: Windows Defender 방화벽에서 Python 허용)
- 노트북 3대 모두 브라우저로 **http://<HUB_IP>:8000** (허브 노트북은 `http://localhost:8000`도 됨) → 카메라 B, C "실시간", 로봇 카드 A·B·C에 Wi-Fi 세기가 보이면 정상.
- 노트북 B, C에서 서버 연결 확인: 브라우저로 `http://<HUB_IP>:8000/api/dogs` → 로봇 A·B·C가 나오면 OK.
- `Address already in use`면 서버가 이미 켜져 있는 것. 그 창을 쓰거나 Ctrl+C로 끄고 다시.

### 3-8. 각자 회전 방향 확인 (1분)
```bash
python brain/teleop.py --dog <내 로봇 IP>
```
- 작은 창을 클릭한 상태에서 `a`(왼쪽 회전), `d`(오른쪽 회전). 키를 떼면 0.3초 안에 멈춤. `x`로 종료.
- **반대로 돌면** 그 로봇은 이후 모든 명령에 `--turn-sign 1`을 붙입니다 (B는 -1로 확인됨).

| 로봇 | turn-sign |
|---|---|
| A | |
| B | -1 (2026-11-12 확인) |
| C | |

### 3-9. 포위 보정 (노트북 C만, 약 10분)
B는 저장소의 `brain/calibration.json`에 보정값과 다듬은 경로가 있습니다(노트북 B는 git pull만 하면 됨). C는 처음입니다.
```bash
# 1) 제자리 회전(왼쪽·오른쪽 한 바퀴)과 1 m 직진 시간 재기. "왼쪽으로 돌았나요?"에 n이면 안내대로 --turn-sign 1 을 붙여 다시
python brain/contain_demo.py calibrate --dog <C_IP> --name C

# 2) C 혼자 포위 → 복귀 시험 (Enter 두 번)
python brain/contain_demo.py run --dog <C_IP> --name C --monitor <HUB_IP>

# 3) 어긋나면 값을 바꿔 다시 시험하고, 맞으면 --save로 저장
python brain/contain_demo.py run --dog <C_IP> --name C --monitor <HUB_IP> --out 0.5 --forward 0.5 --turn-in 95 --turn-back 185 --save
```
- `--out`: 옆으로 빠지는 거리 · `--forward`: 앞으로 가는 거리
- `--turn-in`: 포위 3번째 회전(다시 앞을 보는 회전) · `--turn-back`: 복귀 첫 회전(뒤로 돌기)
- 덜 돌면 각도를 늘리고, 더 돌면 줄입니다 (B는 100°, 190°였음).
- 보정값은 **노트북 C의** `brain/calibration.json`에 저장됩니다. 시연 끝나고 커밋하면 다른 노트북에서도 씁니다.

## 4. 시연 1: 행렬 따라가기

### 배치
```
   C ─ B ─ A  →  (진행 방향, 앞에 2~3 m 빈 공간)
```
- A 뒤에 B, B 뒤에 C. **앞 개 엉덩이에서 뒤 개 코까지 0.12~0.25 m**.
- B 카메라에 A의 마커 ID 1, C 카메라에 B의 마커 ID 2가 정면으로 보이게.

### 명령 (각자 자기 노트북)
**노트북 B:** A(마커 1)를 따라감
```bash
python brain/marker_follow.py --camera http://<HUB_IP>:8000/api/camera/B/stream --dog <B_IP> --name B --monitor <HUB_IP> --show
```
**노트북 C:** B(마커 2)를 따라감. C turn-sign이 1이면 끝에 `--turn-sign 1`
```bash
python brain/marker_follow.py --camera http://<HUB_IP>:8000/api/camera/C/stream --dog <C_IP> --name C --marker-id 2 --monitor <HUB_IP> --show
```
**노트북 A:** A 조종. A turn-sign이 1이면 끝에 `--turn-sign 1`
```bash
python brain/teleop.py --dog <A_IP>
```

### 진행
1. 노트북 B, C 창이 **`STANDBY - READY for EXPLORE`(초록)** 가 될 때까지 기다림. 대시보드 타임라인에 "Dog B/C STANDBY: EXPLORE 준비 완료".
   - 빨강이면 아랫줄 이유: `marker not seen`(마커 높이·방향), `gap 0.40 m`(간격), `dog not responding`(`dog_cmd.py`, `MONITOR`).
2. 진행자 구령 **"따라가기 시작"** → 노트북 C, B 담당이 각자 창을 클릭하고 **스페이스** (둘 다 "따라가는 중"). A가 안 움직이면 B, C도 제자리.
3. 노트북 A: teleop 창 클릭 → `1`(느린 속도) → `w`로 천천히 전진. 직진 1 m → 정지 → 살짝 회전(`q`/`e`) → 직진.
4. 끝나면 노트북 A가 teleop 스페이스(정지) → `x`. 노트북 B, C는 창에서 **`q`** (정지 명령을 보내고 종료).

### 볼 것 · 기록
- B, C가 줄을 유지하며 따라오는 거리(m), 놓친 횟수, 걷다 서다 정도
- 마커를 1.5초 넘게 놓치면 B·C는 마지막으로 본 쪽으로 제자리에서 천천히 돌며 찾음(12초 뒤 포기). **앞 개가 기다리는 기능은 아직 없으므로**, B나 C 담당이 "멈춰"라고 하면 노트북 A가 teleop 스페이스.

## 5. 시연 2: 포위와 재정렬

### 전환
- **노트북 B, C의 따라가기 창은 반드시 `q`로 끕니다.** 일시정지 상태에서도 정지 명령을 계속 보내서 포위 명령과 섞입니다.
- 노트북 A의 teleop도 `x`로 끕니다 (A는 그대로 서 있으면 됨).

### 배치
```
              C 도착 (왼쪽, C 저장값)
   C ─ B ─ A        ■ 침입자 상자 (A 앞 약 0.8 m)
              B 도착 (오른쪽 0.2 m, 앞 0.2 m)
```
- A–B–C를 일렬로 세움 (간격 0.12~0.25 m). B는 **오른쪽**(침입자 둘레 시계 반대), C는 **왼쪽**(시계)으로 빠지니 양옆 1 m씩 비워 두기.

### 명령 (각자 자기 노트북, Enter 대기 상태로 띄워 둠)
**노트북 B:**
```bash
python brain/contain_demo.py run --dog <B_IP> --name B --monitor <HUB_IP> --camera http://<HUB_IP>:8000/api/camera/B/stream
```
**노트북 C:**
```bash
python brain/contain_demo.py run --dog <C_IP> --name C --monitor <HUB_IP> --camera http://<HUB_IP>:8000/api/camera/C/stream
```
- 실행하면 포위·복귀 동작 목록과 시간이 먼저 출력됩니다. 확인 후 진행.

### 진행
1. 진행자 구령 **"하나, 둘, 셋"** → 노트북 B, C가 **동시에 Enter** → 포위 (대시보드 CONTAIN, 경보 이벤트).
   - B: 제자리 오른쪽 90° → 직진 0.2 m → 왼쪽 100° → 직진 0.2 m
   - C: 제자리 왼쪽 90° → 직진 → 오른쪽 회전 → 직진 (C 저장값)
2. **HOLD**: 둘 다 멈춤. 대시보드 "포위 완료, 확인 후 재정렬 명령 대기". 진행자가 위치 확인·사진.
   - 많이 어긋났으면 그 로봇 담당이 `python brain/teleop.py --dog <내 로봇 IP>`로 살짝 조정 후 `x` (HOLD 중에는 포위 프로그램이 명령을 안 보냄).
3. 진행자 구령 **"B 재정렬"** → 노트북 B가 **Enter**: B가 줄 자리로 복귀하고 A 마커를 가운데로 맞춤(최대 ±15°). 노트북 B에 "복귀 완료"가 나올 때까지 기다림.
4. 진행자 구령 **"C 재정렬"** → 노트북 C가 **Enter**: C가 복귀하고 B 마커를 맞춤.
   - **C는 반드시 B가 끝난 뒤에** (C는 B 등의 마커를 보고 방향을 맞추기 때문).
5. 다시 하려면 B, C가 같은 명령을 다시 실행.

### 볼 것 · 기록
- 포위 지점 오차(목표 대비 cm), 복귀 후 줄 자리 오차, 마커 정렬 결과(`가운데 정렬 완료` / `범위 밖`)
- 걸린 시간: 포위 약 20초, 복귀 약 40초 + 정렬

> 한 노트북에서 B·C를 함께 돌리는 방법도 있습니다(`contain_demo.py run --name B,C --dog <B_IP>,<C_IP> ...`, Enter 한 번에 동시 포위, 재정렬 순서 자동). 그 노트북의 `brain/calibration.json`에 B와 C 보정값이 모두 있어야 하므로, C 보정을 커밋·pull한 뒤에 씁니다.

## 7. 문제 해결

| 증상 | 원인 · 해결 |
|---|---|
| 허브: `Address already in use` | 서버가 이미 켜져 있음. 그 창을 쓰거나 끄고 다시 |
| 노트북 B·C에서 대시보드·`/api/dogs`가 안 열림 | 허브 방화벽이 막음(3-7), 또는 다른 Wi-Fi에 붙어 있음 |
| `No route to host` / `Host is down` | 로봇견 IP가 바뀌었거나 `dog_cmd.py`가 안 돎. Thonny Shell에서 IP 확인 후 다시 Run |
| 명령은 가는데 로봇이 안 움직임 | `dog_cmd.py` 멈춤 (LED 꺼짐). Thonny에서 Stop → Run. 배터리 스위치 확인 |
| Thonny: `secrets.py에 NAME ... 추가` / `MONITOR ... 추가` | 그 로봇의 `secrets.py`에 줄이 없음. 3-5대로 다시 저장 |
| Thonny: `OSError: ENOMEM` | Wi-Fi가 느림. 최신 `dog_cmd.py`는 이걸로 죽지 않음 (git pull 확인). 공유기 가까이 |
| 대시보드에 로봇이 안 보이거나 둘이 섞임 | `MONITOR`가 허브 IP가 아님 / `NAME`이 겹침 |
| 따라가기 창: `dog not responding` | 허브에 그 로봇 상태가 안 옴: `MONITOR`, `NAME`, 허브 서버가 최신 코드인지 |
| 따라가기 창: `marker not seen` | 마커 높이·각도·조명. 대시보드 카메라 화면으로 확인 |
| 카메라 영상이 안 나옴 / "오프라인" | 카메라 IP 확인(3-4). 누군가 브라우저로 `:81/stream`을 직접 열어 두면 허브가 못 받음 |
| 마커 반대쪽으로 돎 | 그 로봇에 `--turn-sign 1` |
| 포위 명령인데 안 움직임 | 따라가기 창을 `q`로 안 끔 (정지 명령이 섞임), 또는 teleop이 켜져 있음 |
| `보정값이 없습니다` | 그 로봇 `calibrate` 먼저 (3-9) |
| 포위·복귀 각도가 계속 어긋남 | `--turn-in`, `--turn-back`, `--out`, `--forward` 조정 후 `--save`. 바닥이 바뀌었으면 `calibrate` 다시 |

## 8. 안전 수칙
- 로봇 담당은 항상 자기 터미널에서 **Ctrl+C**를 누를 준비. 모든 프로그램은 끝날 때 정지 명령을 보냅니다. 로봇 쪽도 1초 동안 명령이 없으면 스스로 멈춥니다.
- **한 로봇에는 한 노트북의 한 프로그램만** 명령을 보냅니다 (teleop, 따라가기, 포위를 동시에 켜지 않기).
- 처음 한 번은 **들고 있는 상태로** 명령을 보내 다리 움직임만 확인.
- 사람과 로봇 사이 30 cm 이상. 테이블 위에서는 시연하지 않음.
- 배터리 경고음이 나면 즉시 중단하고 충전.
