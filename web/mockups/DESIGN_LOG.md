## 1. 출발점: 지금 대시보드 진단

요청: "web dashboard 디자인 및 설계 — 지금 있는 것을 정돈하고 깔끔하게, 1안 2안 3안으로 나눠서"

현재 `web/` 대시보드를 새 시나리오(정찰견 A가 등에 LiDAR를 메고 앞장서고, B·C가 ArUco 마커를 따라 줄지어 걷는 순찰)와 비교했습니다.

| 중요도 | 문제 |
|---|---|
| 높음 | 옛 시나리오 기준: 고정된 "Pi + LiDAR" 점, 소리 센서(ReSpeaker) 카드, 역할 "추적견·봉쇄견", 개별 순찰 구역 |
| 높음 | 미션 이름이 옛 것이고 영어만 있음 (PATROL/SUSPECT/ALERT/INTERCEPT/…) |
| 높음 | 경보가 눈에 잘 안 띄고, 증거 사진이 페이지 맨 아래에 있음 |
| 높음 | 조작 버튼 없음 (전체 정지, 일시정지, 인계 완료) |
| 중간 | 카메라 1대만 표시 (A 고정) |
| 중간 | 개 상태가 작은 회색 두 줄, 배터리 부족 색 없음 |
| 중간 | 지도에 탐사한 곳/모르는 곳, 이미 알린 물체, 따라가기·포위 표시 없음 |
| 낮음 | 글자가 작음 (11~13px), 서버 연결 상태만 표시 |

유지할 것: WebSocket 수신, 서버 카메라 중계(`/api/camera/X/stream`), canvas 지도, 외부 라이브러리 없음(오프라인 동작).

## 3. 포위 수정: 시행착오

### 문제
화면을 보면 **정찰견 A는 발견만 하고 B·C 둘이 포위하는 것처럼** 보였습니다.
원인: B·C만 침입자 둘레 0.6 m 원의 ±120° 자리로 가고, A는 발견한 자리(침입자에서 0.5~1.3 m)에 그대로 서 있었습니다.

### 목표
- A·B·C **세 마리가 침입자 둘레 0.6 m에 120° 간격**으로 둘러싸기
- 이동 중에 장애물·벽·침입자·다른 개와 부딪히지 않기

### 확인 방법
가짜 시나리오를 6바퀴(사건 6번) 돌리면서 매 0.05초마다 아래 거리의 최솟값을 측정했습니다.
값이 0이거나 음수면 장애물이나 벽을 뚫고 지나간 것입니다.

| 시도 | 바꾼 것 | 장애물까지 | 벽까지 | 침입자까지 | 개끼리 | 결과 |
|---|---|---|---|---|---|---|
| 1 | A도 0.6 m 원 위 자리로 이동. 원 위 진입점까지 직선으로 간 뒤 원을 따라 돌기 | **0.00** | 0.44 | **0.39** | **0.12** | 세 마리 포위는 됐지만 책상을 뚫고, 서로 겹침 |
| 2 | 바깥 원(0.95 m)을 돌다가 안으로 들어가기, 침입자는 A 근처에서만 생성 | **0.00** | **−0.22** | **0.31** | **0.05** | 방(6×4 m)이 작아 A 근처엔 둘러쌀 공간이 없는 경우가 많음. 벽 밖으로 나감 |
| 3 | 침입자를 "둘러쌀 공간이 있고 A가 볼 수 있는 빈 바닥 중 A와 가까운 곳"에 생성, 바깥 원 0.8 m | **0.00** | 0.25 | 0.60 | **0.01** | 벽 문제 해결. 아직 직선 구간에서 책상을 지나고, 개끼리 겹침 |
| 4 | 직선·원 경로 대신 **10 cm 격자 길찾기(A\*)**: 장애물·침입자(0.5 m 안)·먼저 자리 잡은 개를 피함 | 0.18 | 0.44 | 0.50 | **0.01** | 장애물 해결. 움직이는 개끼리 동시에 길을 건너며 겹침 |
| 5 | **순서대로 출발**: A 도착 → B 출발, C는 B 뒤 0.6 m. 단계 시간 안에 끝나도록 속도 자동 조절 | 0.18 | 0.44 | 0.50 | 포위 0.30 / 복귀 **0.01** | 포위는 해결. 줄로 돌아올 때 B가 이미 도착한 A 자리를 지나감 |
| 6 | 복귀할 때 **먼저 도착한 개의 자리도 피하기** | 0.18 | 0.44 | 0.50 | 0.32 | 모든 단계 해결 |

### 최종 결과 (사건 6번 모두)
- 세 마리 모두 침입자에서 **0.60 m**, 간격 **120° / 120° / 120°**
- 지도에 세 마리를 잇는 **포위망 삼각형** 표시 (이동 중 점선, 완료 후 실선)
- 화면 문구 "B·C 포위" → "A·B·C 3방향 포위"로 수정 (1·2·3안 모두)

## 4. 순찰 경로 수정

### 문제
세 마리가 **사각형 테두리만 겉돌았습니다.** (경로가 꼭짓점 4개짜리 사각형)

### 바꾼 것
- 방 안 경유점 12개를 부드러운 곡선(Catmull-Rom)으로 이어, 책상과 선반 사이를 누비는 경로로 변경
- 처음 만든 곡선은 급하게 꺾이는 곳에서 줄지어 걷는 개 사이가 **0.33 m**까지 좁아짐
  → 경유점 위치를 조금씩 바꿔 가며 가장 완만한 배치를 찾아 **0.38 m**로 개선
  (장애물에서 0.44 m, 벽에서 0.43 m 이상 유지)

## 6. 사이렌 (#6) — 1안에 반영

회의에서 **1안(관제실형)** 으로 정했고, #6 사이렌 알림 범위를 1안에 먼저 넣어 봤습니다.

### 결정한 것
- 알리는 방법 4가지: **사이렌 소리 · 경광등 그림 · 경보 배너 · 브라우저 알림 팝업**
  - 처음 안은 "빨간 화면 깜빡임"이었지만 → 화면 전체 대신 **경광등 그림**이 깜빡이도록 변경
- 휴대폰 푸시 알림은 안 함 (휴대폰 브라우저로 대시보드 주소를 열어 두면 같은 알림이 나옴)

### 화면
- 상단 바 빈 공간(이름과 단계 표시 사이)에 경광등 + 상태 글자 + **"🔔 알림 켜기"** + **"확인"**(울릴 때만)
- 평소엔 회색 경광등, 울리면 빨갛게 깜빡이며 빛줄기가 나옴
- 브라우저는 사용자가 한 번 클릭해야 소리를 낼 수 있어 "알림 켜기" 버튼이 필요

### 언제 울리고 멈추나: 결정 과정

| 순서 | 내용 |
|---|---|
| 1. 후보 정리 | 울릴 때 후보 3개: SUSPECT(의심) / **CONFIRM(범인 확인)** / CONTAIN(포위 시작). SUSPECT는 오탐이 많아 제외 |
| 2. 임시 적용 | 결정 전까지 시안에는 "포위 시작"으로 넣어 둠 |
| 3. 팀에 올린 선택지 | **A. 범인 확인 때**: 가장 빨리 알 수 있음, 확인이 틀리면 잘못 울릴 수 있음<br>**B. 포위 시작 때**: 조금 늦지만 확인이 끝난 뒤라 잘못 울릴 일이 적음 |
| 4. **팀 결정** | **A. 범인 확인(CONFIRM) 단계가 시작될 때 울림** |
| 5. 반영 | 시안의 울림 시점을 확인 단계로 변경. 잘못 울린 경우(오탐으로 탐사 복귀)에는 자동으로 멈추고 기록에 "오탐"으로 남김 |

멈춤은 처음 제안대로 **"확인" 버튼 또는 줄 다시 서기(REGROUP) 시작, 먼저 오는 것** (비상 정지 · 오탐 때도 멈춤). REGROUP 시점은 #7과 함께 정함.

> 시안의 가짜 시나리오는 "의심·확인"이 한 단계(SUSPECT)라서, 그 단계의 뒤쪽 절반을 확인 단계로 보고 울립니다. 실제 대시보드(#17)는 상태 이름이 CONFIRM으로 나뉘므로 그대로 CONFIRM에서 울립니다.

## 8. 시작 버튼 (STANDBY) · 재정렬 버튼

팀장님 설명: **버튼은 시작 / 사이렌 / 재정렬.** 포위를 하면 사이렌이 울리고, 관제가 "됐다" 싶으면 재정렬 버튼으로 신호를 줌.

### 흐름
```
STANDBY 일렬 대기 → 준비 확인 표가 모두 초록 → [▶ 탐사 시작]
→ 지도 만들기 · 순찰 → 의심 · 범인 확인 (🚨 사이렌) → 포위
→ 포위 유지 (버튼을 누를 때까지) → [↺ 재정렬] → 줄 다시 서기 → 순찰 재개
```

### 화면에 넣은 것
| 항목 | 내용 |
|---|---|
| 단계 표시 | 맨 앞에 **STANDBY 대기** 추가 |
| 준비 확인 표 | A·B·C마다 항목을 초록(준비) / 빨강(아직)으로 표시. A: 연결 · 배터리 · 카메라 · LiDAR/SLAM, B: … · 마커 1, C: … · 마커 2 (가이드 8절, #17 댓글 기준) |
| ▶ 탐사 시작 | 모든 항목이 초록일 때만 누를 수 있음. 비상 정지 중에는 못 누름 |
| ↺ 재정렬 | 상단 바 + 경보 배너. **포위 · 인계(HANDOVER) 중에만** 누를 수 있음 |
| 기록 | "준비 완료", "탐사 시작을 누름", "재정렬 신호를 보냄"이 이벤트 목록에 남음 |

### 결정 (2026-11-13)
- 사이렌은 이미 정한 대로 **범인 확인 때** 울림 (6절)
- **재정렬은 버튼을 누를 때만.** 누르지 않으면 계속 포위를 유지함 (예전 시안은 몇 초 뒤 자동으로 줄을 섰음)
- 재정렬 버튼을 누르면 줄 다시 서기가 시작되면서 사이렌도 같이 멈춤

### #7 끝나면 팀과 다시 확인할 것
- [ ] **아무도 재정렬을 누르지 않으면?** 계속 포위만 할지, 일정 시간 뒤 자동 재정렬(또는 알림)을 둘지 — #7 "재정렬 시점"과 함께 확인
- [ ] 포위가 오래 이어지면 배터리가 닳는 문제 (C 배터리가 가장 먼저 낮아짐)
- [ ] 공개 주소(Cloudflare)로 연 화면에서는 시작 · 재정렬 버튼을 회색으로 (#22에서 정하는 `can_command`) — 시안에는 아직 없음

## 10. 카메라 추론 대시보드 시안 (얼굴 5안 · 행동 6안)

팀 회의(2026-11-18)에서 관제실 대시보드 외에 **카메라 추론 대시보드 2개**를 더 만들고, 마지막에 탭 3개(관제실 · 얼굴 · 행동)로 넘어가는 최종 대시보드로 합치기로 했습니다. 이번에는 먼저 두 추론 화면의 시안을 화면별로 3안씩 만들었습니다.

### 얼굴 추론 — 범인인지 판정
- 판정 기준(팀 결정): **명단 두 개 모두 사용.** 허용 명단(팀원)과 경고 명단(범인 역할) 중 어느 쪽과 일치율이 0.60 이상인지 봅니다. 둘 다 미만이면 **미등록(침입자 의심)**입니다.
- 생김새로 "범인 같다"를 추론하지 않습니다. 등록된 얼굴과 같은 사람인지만 봅니다 (정확도 · 차별 문제).
- 후처리 규칙: 일치 기준 0.60 · 최근 5장 중 3장이 같아야 확정 · 40px보다 작은 얼굴은 판정 보류 · 경고 → 미등록 → 허용 순으로 먼저 확정.
- 화면에는 실제 사진 대신 단순한 얼굴 그림을 씁니다.

| 시안 | 이름 | 특징 |
|---|---|---|
| `face1.html` | 판정 카드형 | 큰 카메라 + 큰 판정 카드(허용/경고/미등록/보류), 등록 명단별 일치율 막대, 5장 투표 표시, 판정 기록 |
| `face2.html` | 얼굴 갤러리형 | 다녀간 사람마다 얼굴 카드. 경고 → 미등록 → 허용 순 정렬, 숫자 타일(경고 · 미등록 · 허용 · 지금) |
| `face3.html` | 타임라인 · 기준 조절형 | 60초 타임라인(확정 판정 · 한 장씩 판정 · 실제 정답), **일치 기준 · 확정 장수 · 최소 얼굴 크기를 슬라이더로 바꿔 보며 시험** |

### 행동 추론 — YOLO11n-pose 몸 점 17개로 위험 행동 판정
