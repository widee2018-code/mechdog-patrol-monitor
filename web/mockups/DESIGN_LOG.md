# 대시보드 디자인 시안 작업 기록

작성: 이용석 (담당: `web/`)
대상: `web/mockups/` (1안 · 2안 · 3안 시안, 가짜 데이터로 동작)

> 시안은 아직 팀이 고르지 않았습니다. 고른 안(또는 섞은 안)을 실제 `web/index.html`, `app.js`, `style.css`에 반영하는 것이 다음 단계입니다.

---

## 1. 출발점: 지금 대시보드 진단

요청: "web dashboard 디자인 및 설계 — 지금 있는 것을 정돈하고 깔끔하게, 1안 2안 3안으로 나눠서"

현재 `web/` 대시보드를 새 시나리오(정찰견 A가 등에 LiDAR를 메고 앞장서고, B·C가 ArUco 마커를 따라 줄지어 걷는 순찰)와 비교했습니다.

| 중요도 | 문제 |
|---|---|
| 높음 | 옛 시나리오 기준: 고정된 "Pi + LiDAR" 점, 소리 센서(ReSpeaker) 카드, 역할 "추적견·봉쇄견", 개별 순찰 구역 |
| 높음 | 미션 이름이 옛 것이고 영어만 있음 (PATROL/SUSPECT/ALERT/INTERCEPT/…) |
| 높음 | 경보가 눈에 잘 안 띄고, 증거 사진이 페이지 맨 아래에 있음 |
| 높음 | 조작 버튼 없음 (전체 정지, 일시정지, 인계 완료) |
| 중간 | 카메라 1대만 표시 (A 고정) |
| 중간 | 개 상태가 작은 회색 두 줄, 배터리 부족 색 없음 |
| 중간 | 지도에 탐사한 곳/모르는 곳, 이미 알린 물체, 따라가기·포위 표시 없음 |
| 낮음 | 글자가 작음 (11~13px), 서버 연결 상태만 표시 |

유지할 것: WebSocket 수신, 서버 카메라 중계(`/api/camera/X/stream`), canvas 지도, 외부 라이브러리 없음(오프라인 동작).

## 2. 시안 3개

| 시안 | 특징 |
|---|---|
| **1안 관제실형** (어두운 화면) | 화살표 미션 단계(한/영), 큰 지도, 오른쪽 카메라 3개, 개 카드 3장, 경보 배너 + 인계 완료 버튼 |
| **2안 카드형** (밝은 화면) | 개마다 카드 1장(카메라 + 큰 숫자 4개), 아래에 지도·증거 사진·기록 |
| **3안 사건 중심형** | 평소엔 "순찰 중 · 이상 없음" 한 문장 + 지도. 사건이 나면 화면 전체가 어두운 사건 화면으로 바뀜 |

공통 코드 `mock.js`: 가짜 시나리오(지도 만들기 → 순찰 → 의심·확인 → 포위 → 인계 → 줄 다시 서기 반복), 지도·카메라 그리기.

### 1안 화면 점검에서 고친 것
- 지도 canvas가 끝없이 커지는 문제 → 지도를 감싸는 상자에 크기를 고정
- 시간이 오전/오후로 나오던 것 → `HH:MM:SS` 형식으로 통일
- 지도에서 "모르는 곳" 색이 잘 구분되지 않음 → 색을 더 진하게

## 3. 포위 수정: 시행착오

### 문제
화면을 보면 **정찰견 A는 발견만 하고 B·C 둘이 포위하는 것처럼** 보였습니다.
원인: B·C만 침입자 둘레 0.6 m 원의 ±120° 자리로 가고, A는 발견한 자리(침입자에서 0.5~1.3 m)에 그대로 서 있었습니다.

### 목표
- A·B·C **세 마리가 침입자 둘레 0.6 m에 120° 간격**으로 둘러싸기
- 이동 중에 장애물·벽·침입자·다른 개와 부딪히지 않기

### 확인 방법
가짜 시나리오를 6바퀴(사건 6번) 돌리면서 매 0.05초마다 아래 거리의 최솟값을 측정했습니다.
값이 0이거나 음수면 장애물이나 벽을 뚫고 지나간 것입니다.

| 시도 | 바꾼 것 | 장애물까지 | 벽까지 | 침입자까지 | 개끼리 | 결과 |
|---|---|---|---|---|---|---|
| 1 | A도 0.6 m 원 위 자리로 이동. 원 위 진입점까지 직선으로 간 뒤 원을 따라 돌기 | **0.00** | 0.44 | **0.39** | **0.12** | 세 마리 포위는 됐지만 책상을 뚫고, 서로 겹침 |
| 2 | 바깥 원(0.95 m)을 돌다가 안으로 들어가기, 침입자는 A 근처에서만 생성 | **0.00** | **−0.22** | **0.31** | **0.05** | 방(6×4 m)이 작아 A 근처엔 둘러쌀 공간이 없는 경우가 많음. 벽 밖으로 나감 |
| 3 | 침입자를 "둘러쌀 공간이 있고 A가 볼 수 있는 빈 바닥 중 A와 가까운 곳"에 생성, 바깥 원 0.8 m | **0.00** | 0.25 | 0.60 | **0.01** | 벽 문제 해결. 아직 직선 구간에서 책상을 지나고, 개끼리 겹침 |
| 4 | 직선·원 경로 대신 **10 cm 격자 길찾기(A\*)**: 장애물·침입자(0.5 m 안)·먼저 자리 잡은 개를 피함 | 0.18 | 0.44 | 0.50 | **0.01** | 장애물 해결. 움직이는 개끼리 동시에 길을 건너며 겹침 |
| 5 | **순서대로 출발**: A 도착 → B 출발, C는 B 뒤 0.6 m. 단계 시간 안에 끝나도록 속도 자동 조절 | 0.18 | 0.44 | 0.50 | 포위 0.30 / 복귀 **0.01** | 포위는 해결. 줄로 돌아올 때 B가 이미 도착한 A 자리를 지나감 |
| 6 | 복귀할 때 **먼저 도착한 개의 자리도 피하기** | 0.18 | 0.44 | 0.50 | 0.32 | 모든 단계 해결 |

### 최종 결과 (사건 6번 모두)
- 세 마리 모두 침입자에서 **0.60 m**, 간격 **120° / 120° / 120°**
- 지도에 세 마리를 잇는 **포위망 삼각형** 표시 (이동 중 점선, 완료 후 실선)
- 화면 문구 "B·C 포위" → "A·B·C 3방향 포위"로 수정 (1·2·3안 모두)

## 4. 순찰 경로 수정

### 문제
세 마리가 **사각형 테두리만 겉돌았습니다.** (경로가 꼭짓점 4개짜리 사각형)

### 바꾼 것
- 방 안 경유점 12개를 부드러운 곡선(Catmull-Rom)으로 이어, 책상과 선반 사이를 누비는 경로로 변경
- 처음 만든 곡선은 급하게 꺾이는 곳에서 줄지어 걷는 개 사이가 **0.33 m**까지 좁아짐
  → 경유점 위치를 조금씩 바꿔 가며 가장 완만한 배치를 찾아 **0.38 m**로 개선
  (장애물에서 0.44 m, 벽에서 0.43 m 이상 유지)

## 5. 남은 일
- 팀이 1·2·3안 중 선택 (또는 섞기)
- 선택한 안을 실제 `web/` 대시보드에 반영하고, 기존 `/ws` 메시지(dog, lidar, intruder, camera, mission, event) 처리는 유지
- 전체 정지 버튼은 서버에 `{"cmd":"stop"}`을 보내는 기능이 필요함 → `server/` 영역이라 담당자와 협의 필요
- `server/simulator.py`는 아직 옛 시나리오 → 담당자와 협의
- 이 시안의 포위·경로 계산은 **화면 미리보기용 가짜 움직임**입니다. 실제 로봇 행동(`brain/`)과는 별개입니다.

## 시안 보는 방법
```bash
cd web
python -m http.server 8765
```
브라우저에서 http://127.0.0.1:8765/mockups/ 를 엽니다. 오른쪽 아래 버튼으로 진단 / 1안 / 2안 / 3안을 바꿔 볼 수 있습니다.
포위 장면은 시작 후 약 40초 뒤에 나옵니다.
